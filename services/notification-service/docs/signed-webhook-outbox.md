### Signed webhook outbox
Notification creation and immutable webhook payload commit in one database transaction. Configure trusted tenant destinations in secret-managed `NOTIFICATION_WEBHOOK_DESTINATIONS_JSON`: `{"partner-a":{"endpoint":"https://receiver.example/events","version":"v1","keyId":"key-2026","secretBase64":"base64 of at least 32 random bytes"}}`. Enable dispatch explicitly with `NOTIFICATION_WEBHOOK_ENABLED=true`. No URL is accepted from API callers. HTTPS is required except loopback tests/development; redirects are never followed.

Delivery headers: X-Boodoo-Delivery-Id (stable notification UUID), X-Boodoo-Timestamp (Unix seconds), X-Boodoo-Key-Id, X-Boodoo-Signature (`v1=` plus HMAC-SHA256 hex of `timestamp + "." + deliveryId + "." + exact UTF-8 body`). Receivers verify signature in constant time, reject timestamps outside a short tolerance, and durably deduplicate delivery IDs before acknowledging 2xx. Delivery is at least once: a lost acknowledgement can repeat an already handled event. HTTP delivery never means customer acknowledgement.

Leased batches retry at most eight attempts with 30-second exponential delays capped at one hour. Five-second total HTTP waits and 64 KiB response caps apply. Changed destination versions stop old deliveries. Missing configuration creates UNCONFIGURED rows, never fictitious delivery. GET `/internal/v1/webhook-deliveries/{id}` needs service `notifications:delivery:read`; signed operator POST `/{id}/retry` needs `notifications:delivery:retry` and `{id:eventUUID,reasonCode}`. Redrive only DEAD/UNCONFIGURED, captures current destination version and preserves the original payload. Dead means retry budget exhausted or destination changed; it does not prove the receiver never processed an event.
